# Дозор — система охраны на базе Luckfox

Браузерная панель системы охраны для Luckfox Pico Ultra / Ultra W RV1106. Текущая версия включает прямую трансляцию, журнал событий, настройки, API агента детекции и интерактивную SSH-консоль камеры. Материалы обучения и прототипы детектора сохранены отдельно; сама панель YOLO не выполняет.

## Браузерная панель управления

В папке [admin-panel](admin-panel/README.md) находится сервер на Go и встроенные ресурсы интерфейса. Видео принимает **отдельный go2rtc**: панель открывает его штатный плеер через iframe, без собственного перекодирования, видеопрокси или изменения буфера. Камера передаёт RTSP по Wi-Fi; кодирование выполняется на Luckfox, декодирование — в браузере.

```text
Камера → RTSP-сервер 95.163.220.75:8554/mystream → go2rtc → плеер в браузере
Go-сервер → интерфейс, настройки, журнал, SSH-консоль → браузер
```

### Запуск всего приложения через Docker Compose

Нужны Docker с Linux-контейнерами и Docker Compose v2. В корне репозитория:

```powershell
Copy-Item .env.example .env
```

Укажите в `.env` свой `GUARD_ADMIN_PASSWORD` длиной не менее 12 символов и проверьте `CAMERA_RTSP_URL`. Затем:

```powershell
docker compose up -d --build
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080), логин `admin`, пароль — из `.env`. Compose запускает Go-сервер и go2rtc 1.9.15; настройки, журнал и доверенные ключи SSH сохраняются в Docker volume.

Ссылку источника можно изменить в поле над видео: введите новый RTSP/RTSPS-адрес и нажмите «Применить и запустить» или Enter. Выбранная ссылка сохраняется после перезапуска и имеет приоритет над начальным `CAMERA_RTSP_URL`.

Опубликованы порты `8080/tcp` (панель), `1984/tcp` (go2rtc), `8554/tcp` (RTSP), `8555/tcp` и `8555/udp` (WebRTC). По умолчанию они доступны на этом компьютере. Для доступа из локальной сети задайте `DOZOR_BIND_ADDRESS=0.0.0.0` и `GO2RTC_HOST=<LAN-IP сервера>`.

[Полная инструкция Docker: порты, переменные, данные и диагностика](admin-panel/docs/DOCKER.md).

### Запуск готовой версии в Windows

1. Скачайте архив `Dozor-windows-x64.zip` из [последнего релиза](https://github.com/Vademado/Dozor/releases/latest) и распакуйте его целиком.
2. Проверьте доступность RTSP-сервера. В `admin-panel/go2rtc-standalone.yaml` задан источник `rtsp://95.163.220.75:8554/mystream`.
3. Откройте `admin-panel/scripts/start.cmd` — это отдельное окно go2rtc. Если ваш go2rtc уже работает на порту 1984 с потоком `luckfox`, используйте его.
4. Откройте `admin-panel/scripts/start-admin.cmd` и оставьте оба окна работающими.
5. Перейдите на [http://127.0.0.1:8080](http://127.0.0.1:8080) и нажмите «Запустить» в разделе трансляции.

В разделе «Консоль камеры» введите SSH-пароль своей платы. Пароли, пользовательские настройки, журнал событий и SSH-ключи не включены в публичную поставку. Каталог `data` создаётся при первом запуске.

### Сборка из исходников

Установите [Go 1.26 или новее](https://go.dev/dl/). В PowerShell из корня репозитория:

```powershell
cd admin-panel
.\scripts\build.cmd
.\scripts\test.cmd
```

Для запуска go2rtc скачайте `go2rtc_win64.zip` версии **1.9.15** из [официального релиза](https://github.com/AlexxIT/go2rtc/releases/tag/v1.9.15) и поместите `go2rtc.exe` в `admin-panel/dist/go2rtc/`. Затем используйте два скрипта запуска выше. Go и Node.js для готовой сборки не требуются; Node.js нужен только для `npm run check` при разработке.

## Что реализуется

В ТЗ система должна обнаруживать людей, сохранять за ними track ID, отслеживать траектории, измерять время нахождения в зоне, фиксировать подозрительное поведение, контролировать наличие автомобиля, сохранять доказательную видеозапись, вести журнал и отправлять тревогу в VK. Эти функции не являются одной нейросетью. Рабочая схема состоит из детектора YOLOv8n, трекера ByteTrack, геометрии охраняемой зоны и автомата событий.

Предобученная модель YOLOv8n уже содержит COCO-классы `person` и `car`, поэтому для первичной проверки дообучение не нужно. В этом режиме используются исходные 80 классов COCO. Конфигурация `configs/data.yaml` предназначена для последующего компактного двухклассового варианта `person` и `vehicle`.

## Решение для первого прототипа

- классы детекции: `person`, `vehicle`;
- модель: YOLOv8n, вход 640x640, затем экспорт в ONNX/RKNN INT8;
- обучение: Google Colab на собственном датасете с кадрами именно с камеры и с места установки;
- проверка на ПК: Ultralytics + ByteTrack + видеозапись и журнал;
- запуск на RV1106: C++/RKNN для инференса, лёгкий трекер и конечный автомат событий вне графа нейросети;
- при проблемах совместимости YOLOv8 с конкретной прошивкой предусмотрен запасной вариант YOLOv5n.

## Структура

```text
configs/data.yaml             описание датасета
docs/model_pipeline.md        требования, разметка, обучение и экспорт
prototype/monitor.py          эталонный контур проверки на ПК
scripts/train_yolov8.py       запуск обучения
```

## Быстрый старт обучения

```bash
python scripts/train_yolov8.py --data configs/data.yaml --model yolov8n.pt
```

Скрипт предполагает, что установлен пакет `ultralytics`, а датасет лежит в структуре `dataset/images/...` и `dataset/labels/...`. Перед обучением нужно заменить пути в `configs/data.yaml` и собрать минимум 1500-3000 размеченных кадров с разным освещением, погодой, частичными перекрытиями и пустой зоной.

Подробный порядок работ и критерии приемки описаны в [docs/model_pipeline.md](docs/model_pipeline.md).

## Важная граница применимости

Детектор не может сам по себе доказать угон или намерение человека. Для курсового прототипа подозрительное поведение формализуется измеримыми правилами: длительное нахождение в ROI, приближение к автомобилю, пересечение внутренней зоны, резкая динамика и исчезновение автомобиля после присутствия человека. Пороговые значения должны быть параметрами конфигурации и проверяться на записях с реальной камеры.
