# Консоль камеры — устройство и использование

Раздел «Консоль камеры» открывает настоящий интерактивный SSH-сеанс на плате. Сервер использует Go-пакет golang.org/x/crypto/ssh; локальные ssh.exe, PowerShell и дополнительные серверные приложения не запускаются. Браузер использует локальную копию xterm.js 6.0.0 и addon-fit 0.11.0.

## Подключение

1. Запустите обновлённый scripts/start-admin.cmd, откройте http://127.0.0.1:8080/#console и при необходимости обновите Ctrl+F5.
2. Адрес платы задаётся отдельно от RTSP-ретранслятора переменной `CAMERA_SSH_HOST`; по умолчанию это 192.168.1.199, порт 22, пользователь root. Для USB можно указать 172.32.0.93. В форме адрес можно изменить вручную.
3. Введите существующий пароль SSH платы и нажмите «Подключиться» или Enter в форме. Пароль камеры эта функция не меняет.
4. После подключения терминал принимает обычный ввод, Enter, стрелки, Ctrl+C и последовательности управления. Можно работать с nano и top. Полный экран и изменение размера поддерживаются.
5. Переход в другой раздел панели сохраняет сеанс. «Отключиться», exit или закрытие вкладки завершает его. После разрыва пароль вводится заново; автоматического повторного входа с сохранённым паролем нет.

Кнопка очистки очищает только локальный экран. Ctrl+C отправляет в PTY байт прерывания, а не завершает SSH-подключение. Большая вставка ограничена 64 КиБ за одно действие, чтобы ввод не накапливался бесконечно.

## Проверка SSH-ключей

При подключении читаются data/ssh_known_hosts и существующий файл ~/.ssh/known_hosts пользователя, запустившего Go-сервер. Системный файл читается без изменений. Уже доверенные алгоритмы ключей имеют приоритет при SSH-согласовании. Например, если обычный OpenSSH сохранил ED25519, клиент предпочитает его, даже когда камера также предлагает ECDSA. RSA-ключи используют подписи RSA-SHA2; устаревшие SHA1/DSA не включаются.

При неизвестном ключе сервер возвращает его SHA-256-отпечаток до отправки пароля по SSH. Интерфейс предлагает сверить ключ и подтвердить его. Подтверждённый публичный ключ записывается только в data/ssh_known_hosts. Если ключ действительно отличается от доверенного, автоматическое принятие отключено. InsecureIgnoreHostKey не используется. После перепрошивки платы новый ключ следует отдельно проверить, а не отключать проверку целиком.

Исправление выбора ключа проверено на сервере с одновременно включёнными ECDSA и ED25519. На настоящей плате без пароля и запуска оболочки подтверждено совпадение ED25519 с существующей записью known_hosts.

## Путь данных

```text
xterm.js в браузере
   │  WebSocket того же origin /api/console/ws
   ▼
Go HTTP delivery → console.Connector → SSH TCP :22 → PTY камеры
   ▲                                          │
   └──── исходный stdout/stderr и ввод ────────┘
```

Это отдельный путь управления. Трансляция остаётся в штатном go2rtc-плеере; консоль не меняет её кодек или транспорт.

## Файлы и обязанности

- internal/app/console/ssh.go: ConnectRequest и валидация адреса/размера; Connector.Connect с тайм-аутом; создание SSH-клиента, PTY xterm-256color и оболочки; интерфейс Remote для ввода, вывода, resize, keepalive и закрытия.
- internal/app/console/knownhosts.go: загрузка публичных ключей, подбор приоритета алгоритмов по сохранённым ключам, HostKeyError, подтверждение только неизвестного ключа, потокобезопасная запись собственного known_hosts.
- internal/app/delivery/http/console.go: защищённый WebSocket, первый пакет подключения, передача stdin/stdout/stderr, изменение размера, подтверждения отрисовки, контроль жизненного цикла и ограничение числа сеансов.
- internal/app/delivery/http/handler.go: маршруты и WithConsole для внедрения SSH-подключения. cmd/guard/main.go собирает Connector с каталогом данных и read-only системным known_hosts.
- internal/app/usecase/service.go: ConsoleEvent пишет только открытие, закрытие и неудачную попытку подключения.
- web/assets/console.js: форма и класс CameraConsole, xterm, состояние подключения, подтверждение ключа, ввод, resize и отключение. При навигации терминал остаётся в DOM и сохраняет сеанс.
- web/assets/console.css и web/index.html: оформление, раздел навигации и доступные элементы управления.
- web/assets/vendor/xterm/: закреплённые JS/CSS и MIT-лицензии. Во время работы ничего не загружается с CDN.
- internal/testssh/: тестовый SSH-сервер. Он возвращает введённый текст и никогда не исполняет команды ОС. В production-бинарник он не входит.

## HTTP и WebSocket API

GET /api/console/config возвращает enabled, host, port и user. Пароля в ответе нет. Используется та же авторизация оператора, что у остальных страниц панели; токен агента не даёт доступ к консоли.

GET /api/console/ws переводит соединение в WebSocket. Query-параметры запрещены: секреты не передаются в URL. Origin обязан совпадать с панелью. По обычному HTTP консоль доступна только при loopback-подключении; для удалённого HTTP-клиента требуется HTTPS. TLS за внешним reverse proxy отдельно не настраивался.

Первое текстовое сообщение:

```json
{"type":"connect","host":"192.168.1.199","port":22,"user":"root","password":"пароль текущей попытки","cols":100,"rows":30}
```

При подтверждении неизвестного ключа добавляется trust_fingerprint с показанным SHA256-отпечатком. Он не разрешает заменить известный отличающийся ключ.

После подключения клиент посылает stdin бинарными UTF-8-фрагментами до 8192 байтов. Текстовые управляющие сообщения:

```json
{"type":"resize","cols":120,"rows":40}
{"type":"ack","bytes":8192}
{"type":"disconnect"}
```

Ответы сервера: JSON с type connected, host_key, error или exit; вывод терминала — бинарные сообщения. Xterm отрисовывает полученный блок, затем отправляет ack. Без подтверждений сервер передаёт не более 65536 байтов неотрисованного вывода, затем приостанавливает чтение SSH. Это не позволяет команде с непрерывным выводом бесконтрольно раздувать очередь браузера.

## Пароли, ограничения и завершение

Пароль находится только в памяти текущей попытки подключения. Он очищается из формы, не сохраняется в settings.json, localStorage, URL, известных ключах или журнале панели. Публичные ключи сохранять допустимо: они не являются паролем. Команды и вывод панель не журналирует; история команд и системный аудит самой платы определяются её оболочкой и SSH-сервером.

Одновременно разрешены до восьми SSH-консолей на процесс панели. Это ограничение ресурсов SSH, к количеству зрителей камеры оно не относится. Размер PTY ограничен 2–500 столбцами и 2–200 строками. На подключение отведено до 12 секунд. WebSocket проверяет связь ping/pong, SSH keepalive отправляется раз в 25 секунд с ожиданием до 10 секунд. Закрытие вкладки или остановка сервера отменяет соединение и закрывает SSH-ресурсы.

## Проверки

Go-тесты проверяют первую доверенную запись, отказ при действительно изменившемся ключе, чтение внешнего known_hosts без записи, выбор известного ED25519 при наличии ECDSA, пароль, PTY, Unicode-ввод, Ctrl+C, resize, отмену зависшего согласования и отсутствие паролей/команд в журнале. HTTP-тесты проверяют авторизацию, Origin, запрет секретов в URL и незащищённого удалённого подключения, полный WebSocket/SSH-сеанс и ограничение очереди вывода.

В браузере проверены форма, подтверждение ключа локального SSH-сервера, подключение, ввод и вывод, Ctrl+C, сохранение сеанса при переходе в журнал и отключение. Снимок docs/screenshots/camera-console.jpg показывает именно тестовый сервер, а не настоящую камеру.

Команды проверки: go test ./..., go vet ./..., npm run check. Резервная копия Relese V1 не изменялась и не содержит эту новую функцию.
