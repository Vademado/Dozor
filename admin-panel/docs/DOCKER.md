# Запуск Дозора через Docker Compose

В корне проекта находится `docker-compose.yml`. Он запускает два сервиса: `admin` (Go-сервер с встроенным интерфейсом и SSH-клиентом) и `go2rtc` версии 1.9.15. Luckfox остаётся отдельным устройством в сети. YOLO-агент в эту версию панели не входит.

## Первый запуск

Установите Docker Engine и Docker Compose v2. В Windows подойдёт Docker Desktop в режиме Linux-контейнеров. Перейдите в корень репозитория, где лежит `docker-compose.yml`.

PowerShell:

```powershell
Copy-Item .env.example .env
notepad .env
```

Linux/macOS:

```sh
cp .env.example .env
${EDITOR:-vi} .env
```

В `.env` задайте собственный `GUARD_ADMIN_PASSWORD` длиной не менее 12 символов. Проверьте адрес `CAMERA_RTSP_URL`: по умолчанию `rtsp://192.168.1.199:554/live/0`. Плата и роутер должны быть включены, а адрес камеры должен быть доступен компьютеру с Docker. Пароль админки задаётся отдельно от пароля SSH платы.

Если прежние Go-сервер или go2rtc уже занимают порты 8080/1984/8554/8555, остановите их перед запуском контейнеров.

```sh
docker compose up -d --build
docker compose ps
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080). Логин — `admin`, пароль — `GUARD_ADMIN_PASSWORD` из `.env`. Включите просмотр. Прямая страница go2rtc: [http://127.0.0.1:1984/stream.html?src=luckfox](http://127.0.0.1:1984/stream.html?src=luckfox).

Первая сборка скачивает Go-зависимости и образы. Устанавливать Go или Node.js на компьютер для Docker-запуска не требуется.

## Порты

| Порт хоста → контейнера | Сервис | Назначение |
|---|---|---|
| 8080 → 8080 TCP | admin | Веб-интерфейс, API, SSE и WebSocket SSH-консоли |
| 1984 → 1984 TCP | go2rtc | Штатный веб-плеер, HTTP API и WebSocket |
| 8554 → 8554 TCP | go2rtc | Общий RTSP-выход, например `rtsp://127.0.0.1:8554/luckfox` |
| 8555 → 8555 TCP | go2rtc | WebRTC |
| 8555 → 8555 UDP | go2rtc | WebRTC |

Порты 554 (RTSP) и 22 (SSH) относятся к плате. Контейнеры сами устанавливают исходящие соединения к этим портам; публиковать их на Docker-хосте не требуется.

## Переменные `.env`

| Переменная | Назначение |
|---|---|
| `GUARD_ADMIN_PASSWORD` | Обязательный пароль пользователя `admin`, не менее 12 символов |
| `CAMERA_RTSP_URL` | Входной RTSP-адрес потока `luckfox` |
| `DOZOR_BIND_ADDRESS` | На каком IP хоста публиковать порты; по умолчанию `127.0.0.1` |
| `GO2RTC_HOST` | Адрес Docker-хоста, доступный браузеру, для ICE-кандидата WebRTC |
| `GUARD_AGENT_TOKEN` | Необязательный токен агента, от 24 символов; пустой отключает API агента |

Для доступа с другого компьютера в локальной сети задайте:

```dotenv
DOZOR_BIND_ADDRESS=0.0.0.0
GO2RTC_HOST=192.168.1.156
```

Замените `192.168.1.156` на LAN-IP компьютера с Docker. Открывайте `http://<LAN-IP>:8080`; плеер автоматически использует тот же IP на порту 1984. По умолчанию go2rtc не требует входа: этот режим предназначен для доверенной локальной сети. Публикация в интернете и HTTPS требуют отдельной настройки.

После изменения `.env` примените конфигурацию:

```sh
docker compose up -d
```

Если изменён только `configs/go2rtc.docker.yaml`, перезапустите go2rtc: `docker compose restart go2rtc`.

## Данные и SSH

Именованный том `dozor_admin-data` хранит `/data`: настройки панели, JSONL-журнал и файл доверенных публичных ключей `ssh_known_hosts`. Это отдельное хранилище от папки `admin-panel/data` при обычном запуске Windows. Пароль SSH в том не записывается.

При первом подключении к плате через контейнер проверьте показанный отпечаток SSH-ключа и подтвердите его в панели. Подтверждённый ключ сохранится после пересоздания контейнера.

`.env` исключён из Git, а `admin-panel/.dockerignore` исключает данные, кэш, exe и архивы из контекста сборки.

## Команды управления

```sh
docker compose config --quiet       # проверить конфигурацию без вывода паролей
docker compose logs -f admin go2rtc # логи обоих сервисов; Ctrl+C завершает просмотр
docker compose up -d --build       # собрать и применить обновление
docker compose down               # остановить; именованный том остаётся
```

Не добавляйте `-v` к `down`, если нужно сохранить данные.

## Устройство запуска

`admin-panel/Dockerfile` собирает Linux-бинарник Go с `CGO_ENABLED=0` и помещает его в Alpine; процесс работает от пользователя `dozor`. Compose передаёт `-listen 0.0.0.0:8080`, `-data /data` и `-go2rtc-url http://go2rtc:1984`.

`go2rtc` использует официальный образ и конфигурацию `configs/go2rtc.docker.yaml`, подключённую только для чтения. Подстановка `${CAMERA_RTSP_URL}` и `${GO2RTC_HOST}` выполняется самим go2rtc. Проверка здоровья читает `/api`; Go-сервер запускается после готовности API. Это проверка сервиса, а не подтверждение получения видеокадров с камеры.

Go-сервер читает счётчики по внутренней Docker-сети. Браузер открывает штатный плеер напрямую на опубликованном порту 1984. Пакеты видео не проходят через Go-админку; перекодирование и принудительный режим просмотра не добавлены.

Если панель работает, а видео нет, смотрите `docker compose logs --tail=100 go2rtc` и проверьте доступность камеры. Контейнер не получает автоматического доступа к удалённой домашней сети при переносе на VPS.
