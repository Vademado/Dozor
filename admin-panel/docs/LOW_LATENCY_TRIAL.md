# Проверка H.265 / 720p25 без изменения пути видео

Это пробный профиль камеры. Встраивание страницы go2rtc и работающий процесс go2rtc не меняются. Плавность после применения необходимо измерить; профиль не считается исправлением ошибок RTSP/TCP заранее.

## Исходное наблюдение, 6 ноября 2026 года

Через общий локальный выход go2rtc `rtsp://127.0.0.1:8554/luckfox` за 20 секунд собрано 185 access units с видеоданными: среднее 9,25/с. Максимальная наблюдавшаяся пауза между видеопакетами — 4462 мс. Это измерение доставки сжатых данных, не FPS отображённых браузером кадров и не полная задержка камеры. Дополнительное RTSP-подключение к плате не создавалось: диагностический клиент использовал общий источник go2rtc.

Счётчики пропусков RTP и ошибок сборки, возникшие в начале подключения, не дают самостоятельного доказательства потерь Wi-Fi: подключение могло начаться с середины кадра, а поток проходит через go2rtc. Наблюдавшиеся многосекундные паузы требуют проверки источника и доставки до просмотра.

Плата сообщила power save off, сигнал −57 dBm, TX PHY rate 13 Мбит/с, RX 52 Мбит/с. PHY rate — скорость радиолинка, а не измеренная полезная пропускная способность и не гарантия отсутствия задержек.

## Что меняет scripts/luckfox-low-latency.sh

Только ключи секции `[video.0]` в `/userdata/rkipc.ini`:

| Настройка | Ранее | Пробное значение |
|---|---:|---:|
| width × height | 2304 × 1296 | 1280 × 720 |
| dst_frame_rate_num / den | 25 / 1 | 25 / 1 |
| rc_mode | CBR | CBR |
| max_rate | 2048 | 1536 |
| gop | 50 | 25 |
| gop_mode | normalP | normalP |

Кодек остаётся H.265; для другого кодека скрипт откажется применять профиль. Потоки video.1 и video.2, источник кадров, параметры экспозиции/шумоподавления, сетевые настройки, startup-скрипты и go2rtc не меняются. В режиме CBR этот вариант RKIPC использует `max_rate` как целевой битрейт — см. [официальный исходник RV1106](https://github.com/LuckfoxTECH/luckfox-pico/blob/main/project/app/rkipc/rkipc/src/rv1106_ipc/video/video.c).

Снижение разрешения уменьшает число пикселей примерно в 3,24 раза, ценой детализации. Битрейт уменьшается на 25%. При фактических 25 FPS GOP25 даёт ключевой кадр примерно раз в секунду; это сокращает ожидание восстановления изображения после повреждения опорного кадра, но не гарантирует уменьшения постоянной задержки вдвое.

Скрипт проверяет необходимые ключи и ограничения, сохраняет исходный INI, мягко останавливает только rkipc, повторно сохраняет конфиг после его завершения и запускает rkipc. Штатная остановка S21appinit не вызывается, DHCP не останавливается. Наличие процесса после запуска проверяется, но это не подтверждение выдачи правильного видео.

## Запуск

Сначала нажмите «Остановить» в панели, чтобы закрыть просмотр на время перезапуска камеры. Окно go2rtc оставьте работающим.

В Windows PowerShell:

```powershell
scp "scripts/luckfox-low-latency.sh" root@192.168.1.199:/tmp/luckfox-low-latency.sh
```

В SSH платы:

```sh
sh -n /tmp/luckfox-low-latency.sh
sh /tmp/luckfox-low-latency.sh apply
```

Сохраните напечатанные строки `Backup` и `Rollback`. Перезагрузка не нужна. Старый скрипт `luckfox-smooth.sh` относится к предыдущему профилю H.264 и для этой проверки не используется.

Дайте go2rtc восстановить связь. Для повторного замера с закрытым браузерным просмотром выполните в Windows PowerShell из папки admin-panel:

```powershell
.\dist\streamcheck.exe -source rtsp://127.0.0.1:8554/luckfox -duration 30s
```

После завершения замера нажмите «Запустить» в панели и оцените движение при том же освещении. Для оценки полной задержки покажите камере секундомер и сравните показания оригинала с изображением на экране. Сравнение разных часов без синхронизации не измеряет задержку.

Для отката выполните **точную команду `Rollback`, напечатанную скриптом**, например:

```sh
sh /tmp/luckfox-low-latency.sh restore /userdata/rkipc.ini.before-low-latency-ДАТА-ПРОЦЕСС
```

Резервные копии находятся в `/userdata`, а скрипт в `/tmp` исчезнет после перезагрузки; при необходимости скопируйте его заново. Скрипты автозапуска не правятся. Если прошивка копирует factory INI при загрузке, профиль сбросится — это проверка без изменения загрузочной последовательности.

Если картинка всё ещё распадается на блоки при ровной доставке 25 FPS, отдельно проверяются декодирование H.265 и целостность видеоданных. Если сохраняются многосекундные паузы, дальнейшее уменьшение буфера браузера их не устранит. Конфиг, увеличенный FPS или новый кодек сами по себе не доказывают улучшение.
