# Руководство оператора

## Где что работает

На плате работает камера и штатный `rkipc`, выдающий RTSP. Роутер связывает плату и компьютер. На компьютере запускается **только `guard-admin.exe`**, а в браузере открывается [панель](http://127.0.0.1:8080). Видеобиблиотеки уже входят в исполняемый файл. Дополнительный агент нужен для YOLO, трекинга, тревог и подтверждения режима охраны.

## Запуск и остановка

1. Включите роутер и плату, дождитесь Wi-Fi.
2. Запустите `scripts/start.cmd` и оставьте окно работающим.
3. Откройте `http://127.0.0.1:8080` в Chrome/Edge.
4. Укажите RTSP-адрес и нажмите «Запустить».

Рекомендуется закрепить IP платы на роутере по MAC `b8:41:d9:fe:59:0f`. Если адрес изменился, меняется и адрес источника. Старые вкладки go2rtc/порт 1984 больше не используются; их можно закрыть.

«Остановить» прекращает **просмотр панели и её RTSP-сеанс**, но не останавливает камеру на плате и не меняет политику охраны. Переход в другой раздел освобождает WebRTC-подключение текущей вкладки; общий RTSP-сеанс остаётся доступным для других вкладок. После возврата плеер подключается снова. `Ctrl+C` в окне сервера завершает панель.

## Кнопки плеера

- **Запустить:** проверить и сохранить адрес, включить прямое RTSP-подключение.
- **Круговая стрелка:** пересоздать браузерное WebRTC-соединение.
- **Снимок кадра:** скачать PNG текущего изображения без рамки ROI. Сохранение выполняет браузер на компьютер.
- **Полный экран:** увеличить видео; выход `Esc`.
- **Звук:** в текущем видеопрофиле аудио отсутствует, кнопка отключена.

LIVE появляется только после получения кадров браузером. Открытый HTTP-порт или успешное SDP-согласование сами по себе не означают наличие видео. При отсутствии новых кадров больше 10 секунд плеер повторяет соединение с увеличением интервала до 30 секунд. RTSP-клиент также самостоятельно восстанавливает подключение после обрыва.

## Показатели

| Показатель | Смысл |
|---|---|
| Разрешение | `videoWidth` × `videoHeight` полученного браузером кадра |
| FPS | Частота представленных браузером кадров, измеренная frame callback; не FPS нейросети |
| Входящий поток | Скорость RTP-байтов, принятых Go-сервером от камеры, по разнице счётчиков |
| Потеряно при выводе | Счётчик браузерного декодера; не потери Wi-Fi-пакетов |
| Джиттер-буфер | Разность `jitterBufferDelay` / разность `jitterBufferEmittedCount` WebRTC за интервал; не полная задержка от камеры |
| Без нового кадра | Сколько времени браузер не получал новый кадр |
| Сеанс | Продолжительность просмотра в текущей странице, не uptime платы |
| Кодек | Кодек, реально согласованный WebRTC-плеером |

«—» означает, что данных пока нет или соответствующий браузерный API недоступен. Часы поверх плеера показывают время компьютера оператора. Метрики детектора поступают отдельно от агента и не генерируются панелью.

## Зона наблюдения

Дождитесь видео, нажмите «Изменить границы», протяните прямоугольник на кадре и нажмите «Сохранить». Координаты нормированы в диапазон 0–1. Например, `x=0.1,width=0.8` — отступ 10% и ширина 80% кадра. При рисовании учитывается фактическая область изображения с чёрными полями. Слишком маленькая/выходящая за кадр зона отклоняется сервером. Переключатель выключает использование зоны, сохраняя границы.

Преобразование в пиксели: `left=x*W`, `top=y*H`, `right=(x+width)*W`, `bottom=(y+height)*H`. Отрисованная рамка — желаемая политика. Реальная обработка зоны начнётся только в агенте, который прочитал и применил эту политику.

## Режим охраны

«Включить охрану» сохраняет `armed=true` и новую `revision`. До ответа агента отображается «Ожидаем подтверждение». Подтверждение действительно, когда свежая телеметрия сообщает ту же версию и режим. Через 15 секунд без телеметрии агент считается отключённым, подтверждение снимается. Остановка просмотра не снимает с охраны.

Порог уверенности, время пребывания в зоне и пауза уведомлений также сохраняются в политике, а исполняются агентом. После изменения политики агент должен подтвердить новую версию. Две вкладки не могут молча перезаписать старую политику: устаревшая запись получает HTTP 409; обновите страницу перед повторным редактированием.

## Журнал

Показывает действия оператора, ошибки RTSP/WebRTC и события детектора. Поиск работает по сообщению/типу, фильтры — по источнику и уровню. Время на диске UTC, на экране — локальное время браузера. «Экспорт JSONL» скачивает до 5000 подходящих записей от новых к старым. Одинаковые события плеера ограничены одним событием типа за 30 секунд на сервере.

## Диагностика без видео

**На компьютере в командной строке Windows:**

```bat
ping -n 3 192.168.1.199
ssh root@192.168.1.199
```

Если плата не видна через Wi-Fi, подключите USB и войдите через `ssh root@172.32.0.93`.

**В терминале платы после входа по SSH:**

```sh
wpa_cli -i wlan0 status
ip -4 addr show wlan0
ps -ef | grep '[r]kipc'
netstat -lnt | grep ':554'
```

Нужны `wpa_state=COMPLETED`, актуальный IP, процесс rkipc и слушающий порт 554. Предупреждение об отсутствующем `/proc/net/tcp6` не мешает IPv4. Используйте `ps -ef`, а не `ps w`, который может не показать фоновые процессы.

**На компьютере в PowerShell:**

```powershell
Test-NetConnection 192.168.1.199 -Port 554
```

| Сообщение | Что проверять |
|---|---|
| RTSP: тайм-аут | Роутер, питание, правильный IP, Wi-Fi, доступность порта |
| Порт не принимает соединение | Запущен ли rkipc на плате |
| Неверный логин/пароль | Учётные данные в RTSP-адресе; это не обязательно пароль SSH |
| Поток не найден | Путь `/live/0`, наличие камеры |
| Кодек недоступен | Поддержка кодека и профиля камеры именно в WebRTC браузера; для HEVC см. [H265.md](H265.md) |
| RTSP подключён, WebRTC без кадров | Поддержка H.264/H.265 браузером, наличие ключевых кадров, доступность локальных ICE-адресов |

Если видео работало и зависло, проверьте `free -m` и сообщения `dmesg` на плате. Не отключайте целиком брандмауэр для диагностики: при необходимости разрешите конкретное приложение в доверенной локальной сети. Для локального просмотра используйте браузер на том же компьютере, что и сервер.

## Обновление

Остановите сервер, выполните `scripts/build.cmd`, запустите `scripts/start.cmd`, обновите браузер. Сохраните `data`, если нужны предыдущие настройки и события. Для переноса на другой Windows-компьютер достаточно готового exe и при необходимости каталога данных; Go нужен для сборки исходников.
